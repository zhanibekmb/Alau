# План: аккаунты и демо-пэйволл

Составлен 2026-11-08 на ревью `/plan-ceo-review` (режим HOLD SCOPE). Опирается на дизайн-документ `~/.gstack/projects/Alau/janib-unknown-design-20261104-183449.md`: Next.js, PostgreSQL + Drizzle, Better Auth на своём сервере, хостинг в Казахстане.

## Цель

Читатель бесплатно доходит до кульминации книги, видит тарифы и может создать аккаунт. Настоящих платежей нет: Kaspi и эквайринг отложены. Задача — построить доступ по аккаунтам и узнать, какой тариф выбирают читатели.

### Решение о доступе к главе

Чистая функция `canReadChapter` в `src/lib/access.ts`, без базы внутри:

```
license действует? ── нет ─▶ gone (410)
        │ да
chapter <= freeChapters  ИЛИ  license.allows.paidAccess = false ── да ─▶ ok
        │ нет
есть пользователь? ── нет ─▶ login_required (401)
        │ да
Premium с expiresAt > now  ИЛИ  куплено это произведение? ── да ─▶ ok
        │ нет
payment_required (402)
```

Проверка доступа идёт **до** ответа 304 по ETag: иначе браузер с закэшированной главой прочитает её без доступа. Платные главы отдаются с `Cache-Control: private, no-cache`.

### Поток кнопки «Купить»

```
пэйволл ─ выбор тарифа ─▶ вошёл? ── нет ─▶ /login?next=… ─▶ обратно к пэйволлу
                             │ да
                             ▼
            POST /api/paywall/choice {plan, work, slug, chapter}
                             │
        PAYMENTS_MODE = demo ┼─ interest (по умолчанию и при ошибке настройки)
               ▼                         ▼
   entitlement (повторное         событие plan_chosen,
   нажатие ничего не дублирует)   ответ «оплата скоро откроется»
               ▼
   читалка грузит главу снова
```

### Состояния доступа

```
нет доступа ──demo: single_book──▶ книга навсегда (expiresAt = null)
нет доступа ──demo: premium─────▶ Premium активен ──expiresAt <= now──▶ истёк
истёк ──demo: premium снова──▶ активен (новая запись; старые не меняются)
Невозможно: interest-режим создаёт доступ; доступ без user_id; single_book без work.
```

## Данные (Drizzle, миграции в репозитории)

- Таблицы Better Auth: `user`, `session`, `account`, `verification` (генерирует CLI Better Auth).
- `entitlements`: `id`, `user_id`, `kind` (`single_book | premium_monthly | premium_annual`), `work` (null для Premium), `source` (`demo`, позже `kaspi`), `starts_at`, `expires_at` (null для книги), `created_at`. Уникальность `(user_id, work)` для `single_book`. Индекс `(user_id)`.
- `paywall_events`: `id`, `user_id` (null для гостя), `anon_id` (случайный id из браузера), `type` (`paywall_shown | plan_chosen | signup | demo_unlock`), `plan`, `work`, `slug`, `chapter`, `created_at`. Индекс `(type, created_at)`.
- `reading_progress`: ключ `(user_id, slug)`, `page`, `total_pages`, `finished`, `updated_at`.
- `saved_words`: ключ `(user_id, gloss_id)`, `slug`, `page`, `sentence`, `saved_at`.

Изменения контента: у книги появляются `work` (общий id всех уровней, например `secret-of-lake-bakaly`), `freeChapters` и `price`. Обеим книгам `paidAccess: true`.

Роль admin задаётся переменной `ADMIN_EMAILS`: так не нужен отдельный интерфейс для ролей.

## Карта ошибок

| Место | Что ломается | Что видит читатель | Лог |
|-------|--------------|--------------------|-----|
| GET главы | Нет связи с базой при проверке доступа к платной главе | «Тарау жүктелмеді», кнопка «Қайталау» (503). Бесплатные главы работают без базы | да, slug и глава |
| GET главы | Сессия истекла | Окно входа, после входа та же страница | нет |
| Регистрация | Email уже занят | «Бұл email тіркелген. Кіріңіз» | нет |
| Регистрация | Короткий или пустой пароль, неверный email | Подсказка у поля, форма не уходит | нет |
| Вход | Неверный пароль | «Email немесе құпиясөз қате» (без уточнения, какое из двух) | да, без пароля |
| Вход | Слишком много попыток | «Кейінірек қайталаңыз» (429, лимит Better Auth) | да |
| POST choice | Неизвестный тариф или книга | 400, пэйволл остаётся открытым | да |
| POST choice | Двойное нажатие | Одна запись, второй ответ тот же | нет |
| POST choice | `PAYMENTS_MODE` не задан или с опечаткой | Режим interest, доступ не открывается | предупреждение при старте |
| POST import | Слишком большие или битые данные | Импорт пропущен, локальные данные остаются, повтор при следующем входе | да |
| /admin/paywall | Не admin или не вошёл | 404 | да |

## Безопасность

| Угроза | Вероятность | Ущерб | Защита |
|--------|-------------|-------|--------|
| Подбор паролей | средняя | высокий | Лимит Better Auth на вход, хэш scrypt |
| Открыть платную главу без доступа | высокая | средний | Проверка на сервере до 304, `private` кэш |
| Подделать тариф или цену в запросе | средняя | средний | Сервер берёт цену и срок из своего списка тарифов |
| Бесплатный доступ на публичном сайте через demo | средняя | высокий | По умолчанию interest, demo только явной переменной |
| Чужие данные по id | низкая | высокий | Все `/api/me/*` берут `user_id` только из сессии |
| Утечка email | низкая | высокий | База в Казахстане, email не уходит в аналитику |
| Большой импорт гостя | низкая | низкий | Лимит размера тела и числа слов (5 000) |

Секреты: `BETTER_AUTH_SECRET`, `DATABASE_URL`, `ADMIN_EMAILS`, `PAYMENTS_MODE` только в `.env`. В репозитории лежит только `.env.example`.

Не для кода, но до публичного запуска аккаунтов нужно получить ответ юриста о хранении персональных данных (вопрос 3 дизайн-документа).

## Тесты

Карта покрытия (из инженерного ревью). Сейчас покрыт 1 путь из 24, все остальные перечислены ниже как обязательные тесты.

```
КОД                                                  ПУТИ ПОЛЬЗОВАТЕЛЯ
src/lib/access.ts canReadChapter                     Гость → пэйволл → регистрация → демо-покупка [→E2E]
  ├── лицензия отозвана → gone                       Двойное нажатие «Купить» → 1 запись
  ├── глава ≤ freeChapters → ok                      Сессия истекла посреди книги → вход → та же страница
  ├── paidAccess=false → ok                          Сеть пропала во время покупки → кнопка снова активна
  ├── гость → login_required                         Неверный пароль → общее сообщение
  ├── Premium активен / истёк (граница now)          6-я попытка входа → 429
  └── книга куплена на другом уровне → ok            /admin/paywall не-админу → 404
src/lib/serve.ts serveChapter
  ├── CRITICAL: старый ETag без доступа → 402, не 304 [→E2E]
  └── лицензия, 304, 410 (уже есть в alau.test.ts)
POST /api/paywall/choice: demo / interest / пустой режим / неизвестный тариф
Импорт гостя: пустые, битые, слишком большие данные; anon_id связывает события
BookInfo.freeChapters совпадает с границей на сервере (один тест на оба)
```

Юнит (Vitest, без базы, `npm test`):
- `canReadChapter`: бесплатная глава, глава после границы, гость, Premium активен и истёк, книга куплена на другом уровне того же произведения, `paidAccess: false`, отозванная лицензия.
- Режимы оплаты: пустой, неверный, `demo`, `interest`.
- Слияние прогресса и слов: пустые данные, конфликт страниц, дубликаты слов, превышение лимита.

- `BookInfo.freeChapters` и `paidAccess` равны тем, что использует `canReadChapter`.

С базой (`npm run test:db`, файлы `*.db.test.ts`, база `alau_test`, таблицы очищаются перед каждым файлом):
- После входа с `anon_id` прошлые события гостя получают `user_id`.
- `POST /api/paywall/choice` дважды подряд даёт одну запись.
- Глава после границы: 401 для гостя, 402 без доступа, 200 с доступом. С тем же ETag без доступа приходит 402, а не 304.
- `/admin/paywall` для обычного пользователя отвечает 404.

E2E (Playwright, десктоп и 360 px): гость читает до кульминации → пэйволл → регистрация → демо-покупка → следующая глава открыта, прогресс и слова гостя на месте.

Самый важный тест: закэшированная платная глава не открывается без доступа.

## Наблюдаемость

- События `paywall_events`: показ пэйволла, выбор тарифа, регистрация, демо-открытие.
- `/admin/paywall`: показы, выборы по тарифам, регистрации; по книге и уровню; за 7 и 30 дней; доля «выбрали тариф / увидели пэйволл».
- Логи сервера с причиной отказа (`login_required`, `payment_required`) и без личных данных.
- Предупреждение при старте, если `PAYMENTS_MODE` не задан.

## Выкладка

- Рабочего сервера пока нет, поэтому этап проверяется локально.
- Миграции Drizzle лежат в репозитории и только добавляют таблицы, старые данные не трогают.
- Откат: `PAYMENTS_MODE=interest` и `paidAccess: false` у книг. Тогда главы снова открыты, а таблицы остаются.

## Не входит в этот план

- Kaspi, карты, автопродление, чеки: отложено решением D1.
- ИИ-перевод и лимит «5 в день»: на сайте нет ИИ-перевода (D8).
- Восстановление пароля по почте: нужен почтовый сервис (D3).
- Вход через Google и по ссылке на почту (D3).
- Скидки, подарки, семейные тарифы: режим HOLD SCOPE.
- Отдельный уровень C1 в каталоге: C1 пока показан как B2.
